The Black Box Engine

A hybrid, multi-agent orchestration engine that turns a project's spec into its two deliverables — a strategy website and a fully configured Odoo 19 ERP. It is project-agnostic: point it at any projects/<name>/ and it builds. Casa Escondida Anilao is the reference example, not the engine.

Hybrid runtime Multi-project Pipelines 7 loops Agents CLI

The idea

A project spec goes in. A website and an ERP come out.

Everything project-specific — counts, personas, branding, copy, room/site data — lives as data under projects/<name>/. The engine reads the selected project's spec and drives two pipelines, checking a hard verification gate after every stage. Engine code holds zero project facts: a new project builds with no code changes.

Deterministic core

Runs both builds with the standard library + the Odoo XML-RPC client and a local build/deploy. No API key required.

Reasoning layer

When ANTHROPIC_API_KEY is set, an Anthropic-SDK loop fixes gaps and grounds website copy via Corrective-RAG.

Project-agnostic

Counts and content come from the project spec; Casa Escondida is one project among many.

Hybrid runtime

Two halves. The reasoning half is optional.
ALWAYS ON

Deterministic harness

Sequences each enabled pipeline's stages, runs every write through idempotent tools, checks each gate, persists state, resumes. Needs only the relevant env vars — or nothing at all in --dry-run.

+
WHEN KEYED

Anthropic reasoning layer

A manual tool-use (ReAct) loop on claude-opus-4-8 with adaptive thinking. Decides how to satisfy a gap and grounds copy — but every write still flows through the same idempotent, gated tools.

Multi-project

Engine vs. project — a strict separation

blackbox/ — the engine

Project-agnostic. Orchestrator, pipelines, loops, verification logic, connection tiers, tools. No project facts live here.

projects/<name>/ — the input

project.json (manifest + enabled deliverables), odoo-build-spec/, site-spec/, and inputs/. Selected via --project / BLACKBOX_PROJECT.

projects/casa-escondida/ → blackbox run → strategy website + Odoo 19 ERP
Acceptance bar: a second project added under projects/<name>/ builds with zero changes to blackbox/.

Connection tiers

Pick the highest-fidelity path available — reuse connect/
TIER 1

SSH

Odoo.sh via ODOO_SH_HOST. Used for custom-module deploy.

TIER 2 · primary

API

XML-RPC via xmlrpc_client. All ERP data stages run here.

TIER 3

Browser

Last resort. Forced for SaaS "Install an Industry".

Some prerequisites cannot be done over the API (SaaS industry activation; chart-of-accounts swap needing an empty-books window). The engine detects their absence and reports them as manual steps — it does not fake them. Website deploy target + credentials come from the project's deploy.json and env.

Command line

Project-scoped verbs
python -m blackbox projects                                  # list projects under projects/
python -m blackbox probe  --project casa-escondida          # probe connection, print tier
python -m blackbox run    --project casa-escondida --dry-run # both pipelines vs fakes (no net, no key)
python -m blackbox run    --project casa-escondida --deliverable odoo --yes
python -m blackbox verify --project casa-escondida --stage 7
python -m blackbox report --project casa-escondida          # counts vs targets, deviations

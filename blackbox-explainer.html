The Black Box Engine

A hybrid, multi-agent orchestration engine that autonomously builds the Casa Escondida Anilao Odoo 19 ERP from a machine-readable spec — running deterministically with no API key, and adding an Anthropic reasoning layer when one is present.

Hybrid runtime 9 stages 7 loops Agents Targets CLI

The idea

A spec goes in. A fully populated ERP comes out.

Everything about the build lives as data in odoo-build-spec/ — modules, the data model, demo-data targets, automations, and the connection strategy. The engine reads that spec and drives a real Odoo 19 instance through nine ordered stages, checking a hard verification gate after each one. It never invents facts the spec already states, never fakes a green gate, and re-runs without creating duplicates.

Deterministic core

Runs the whole build with the standard library + the Odoo XML-RPC client. No API key required.

Reasoning layer

When ANTHROPIC_API_KEY is set, an Anthropic-SDK agent loop fixes gaps and composes realistic demo values.

Idempotent

Search-before-create on natural keys means every re-run converges to the same state instead of duplicating it.

Hybrid runtime

Two halves. The reasoning half is optional.
ALWAYS ON

Deterministic harness

Sequences the 9 stages, runs every Odoo write through idempotent tools, checks each verification gate, persists state, and resumes. Needs only ODOO_* env vars — or nothing at all in --dry-run.

+
WHEN KEYED

Anthropic reasoning layer

A manual tool-use (ReAct) loop on claude-opus-4-8 with adaptive thinking. Decides how to satisfy a gap and composes demo values — but every write still flows through the same idempotent, gated tools.

Scope is locked to the Odoo-build half (connect → install → configure → data → POS/booking → transactions → invoice/pay → automations → QA). Website/strategy-site generation is out of scope.

Idempotency & ordering

Why a re-run never duplicates

Natural keys

  • Products → default_code
  • Rooms → stock.lot.name (STD-01…)
  • Partners → email (fallback name + phone)
  • Sale orders → client_order_ref (CE-<channel>-<seq>)

Strict ordering

CoA + taxes → currencies → pricelists → partners → products → resources → orders → confirm → invoice → register payment.

Never invoice before CoA / taxes exist

Two-pass confirm/post: create all drafts first, then confirm/post in a separate, resumable pass.

Connection tiers

Pick the highest-fidelity path available — reuse connect/
TIER 1

SSH

Odoo.sh via ODOO_SH_HOST. Used for custom-module deploy.

TIER 2 · primary

API

XML-RPC via xmlrpc_client. All data stages run here.

TIER 3

Browser

Last resort. Forced for SaaS "Install an Industry".

Some prerequisites cannot be done over the API (SaaS Hotel-industry activation; chart-of-accounts swap needing an empty-books window). The engine detects their absence and reports them as manual steps — it does not fake them.

Command line

Four verbs
python -m blackbox probe                       # probe connection, print recommended tier
python -m blackbox run --dry-run               # full 9-stage build vs FakeOdoo (no net, no key)
python -m blackbox run --from-stage 3 --yes    # live build; auto-approve non-destructive gates
python -m blackbox verify --stage 7            # run one stage's verification gate
python -m blackbox report                      # counts vs targets, deviations
